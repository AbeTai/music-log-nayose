# 楽曲ログのアーティスト名名寄せシステム

Apple Music, Spotify, YouTubeなど複数チャネルから取得した楽曲ログにおいて、表記揺れのあるアーティスト名を統一するシステムです。

## 機能

- サンプルデータの自動生成（日本の人気アーティストの表記揺れを含む）
- 最小限の前処理（アーティスト名の重要な部分を保持）
- **効率的な距離計算**
  - ブロッキング戦略による計算量削減
  - rapidfuzzによる高速レーベンシュタイン距離計算
  - scipy.sparseによる疎行列を使った距離行列構築
- 複数の距離メトリクスによる候補ペア抽出
  - レーベンシュタイン距離行列
  - BM25スコア行列
- Gemini APIを使用した高精度な名寄せ判定
- アーティスト名マスタデータの自動生成

## セットアップ

### 1. 依存ライブラリのインストール

```bash
pip install -r requirements.txt
```

### 2. Gemini API キーの設定

```bash
export GEMINI_API_KEY="your_api_key_here"
```

## 実行方法

```bash
python artist_deduplication.py
```

## 出力ファイル

スクリプトを実行すると、以下の3つのファイルが生成されます：

1. **sample_artists.csv** - 表記揺れを含むサンプル楽曲ログデータ（100件）
2. **candidate_pairs.json** - 距離メトリクスで抽出された候補ペア
3. **artist_master.json** - Gemini APIで判定された正規化アーティスト名マスタ

## サンプルデータに含まれるアーティスト

- YOASOBI（表記揺れ例: YoOSBI, YOASOBI ビデオ版あり）
- BTS（表記揺れ例: B T S, B.T.S., 防弾少年団）
- Ado（表記揺れ例: Ado (Official), Ado【公式】）
- BABYMETAL（表記揺れ例: ＢＡＢＹＭＥＴＡＬ, Baby Metal）
- Official髭男dism（表記揺れ例: ヒゲダン, 髭男dism）
- 米津玄師（表記揺れ例: Kenshi Yonezu, よねづけんし）
- その他、日本の人気アーティスト多数

## パラメータ調整

`artist_deduplication.py` の冒頭で以下のパラメータを調整できます：

```python
LEVENSHTEIN_THRESHOLD = 5  # レーベンシュタイン距離の閾値
BM25_THRESHOLD = 0.5       # BM25スコアの閾値
SAMPLE_SIZE = 100          # サンプルデータ件数
```

## 処理フロー

1. サンプルデータ生成 → `sample_artists.csv` 出力
2. データ読み込み
3. 前処理適用（空白削除、付加情報削除）
4. **ブロッキング**（アーティスト名を類似度の高そうなグループに分割）
5. **距離行列の構築**
   - レーベンシュタイン距離行列（疎行列、ブロック内のみ計算）
   - BM25スコア行列（密行列）
6. 候補ペア抽出（距離行列から閾値を満たすペアを抽出） → `candidate_pairs.json` 出力
7. Gemini API呼び出し → 表記揺れ判定
8. マスタデータ生成 → `artist_master.json` 出力

## 技術的な特徴

### ブロッキング戦略
計算量を削減するため、以下の3つのキーでアーティスト名をブロック化：
1. 正規化後の最初の2文字
2. 正規化後の最初の1文字
3. 名前の長さ（3文字ごとにグループ化）

同じブロック内のペアのみレーベンシュタイン距離を計算することで、全ペア比較よりも大幅に効率化されます。

### 距離行列
- **レーベンシュタイン距離**: scipy.sparseのdok_matrix（疎行列）で保存
- **BM25スコア**: numpyの密行列で保存
- 距離行列を事前計算することで、候補ペア抽出が高速化されます

- APIのレート制限に注意してください
- サンプルサイズが大きいと処理時間が長くなります
